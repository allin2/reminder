## 2. 目标与范围

最终目标：业务规则有唯一来源；`app-core.js` 只装配依赖、启动应用和暴露薄测试入口；事务、原生协调、表单、视图和平台能力有清楚的模块归属。用户操作、数据格式、已有成功与失败行为保持一致。

必须完成：

1. 移除 app-core 中解析、重复、勿扰、截止阶段等备用业务实现及运行时覆盖块。
2. 移除 native-reminders 中重复的勿扰算法、缺规则模块时的简化截止保护；继续检查反馈、送达证据等缺模块时的静默分支。
3. 消除日期工具同名导出覆盖，区分确实不同的业务语义。
4. 拆出全部主要职责，包含巨大的 `bind()`、通知实验室、设置引导及测试 hook；不能把原 IIFE 整体换个文件名。
5. 同步生产脚本顺序、离线缓存、测试加载和 Capacitor 资源链，并建立防止重复实现和漏加载复发的检查。

不包含：改 schema 5、改存储 key/后端、引入框架/bundler/新运行依赖、重新设计 UI、改变提醒次数或权限策略、修复既有 OEM 冷进程送达问题、接通目前未接入的 JSON/ICS 导入导出模块、清理旧证据或 APK。诊断界面本轮只搬移，不顺带删除、隐藏或改为懒加载。

“双实现移除”指当前可执行源码中同一规则的重复算法；构建复制的相同资源、历史证据中的旧源码、不同平台的必要适配不属于重复实现。不得通过全仓删除 `fallback` 字样完成任务。

## 3. 唯一来源清单与已知陷阱

以下位置按基线记录，以符号为准，搬移后更新到新路径。

| 规则 / 当前重复点 | 最终归属与要求 |
| --- | --- |

| `nextRepeatTrigger`、`repeatLabel`、`nextRepeatPreview`；core 约 261、1948、2134 | `lib/repeat.js` 唯一实现；保留 calendar/ack 两种锚点、月末、月底短月及稳定派生语义 |

| Feedback / DeliveryEvidence 缺失时的备用文案、规则或空操作 | 已加载到生产的规则模块视为必需依赖；删除因脚本缺失产生的另一套业务行为，保留“设备没有可读证据”的真实状态 |
| storage/native 对象不存在时静默运行 | 必需 JS 模块缺失属于装配错误；无 IDB、无 Capacitor、权限被拒、桥延迟注入属于运行能力差异，两者分开处理 |

**日期函数不能按同名直接合并。** 当前 `parse-cn.js` 的 `nthWeekdayOfNextMonth` 按具体时刻比较，`repeat.js` 按日比较以防周期原地打转；生产解析器闭包中的函数也不会随全局同名覆盖而改变。先固化两种行为，抽取共同的“求某月第 N 个星期几”原语；首个触发候选与下一周期推进分别显式命名或传入明确策略。不能为了去重统一成会改变日期的比较方式。兼容导出如需保留，只能委托同一来源，不得再有算法体。

保留的降级必须列表登记：Web 无 Capacitor、IDB 不存在/暂时打不开、通知权限拒绝、原生桥延迟或调用失败、浏览器分享/下载与 Android SAF、无 URL 构造器时的保守链接检查。每项写清触发条件、唯一实现、失败反馈和覆盖用例。

`app.js` 是 PRD 页交互，当前产品 `index.html` 不引用它；不得当作旧 app-core 删除。`lib/import-*`、`lib/export-format.js` 也不能因为本次拆分被顺手接入或删除。

依赖方向：纯规则 → 模型/基础存储 → 应用服务 → UI 控制器 → 入口装配。模块不得反向导入 app-core，不引入全局事件总线、通用服务定位器或把全部函数塞进一个共享 `ctx` 来掩盖循环依赖。

必须特别处理原 IIFE 的活绑定：`withDraftState` 会临时切换状态，加载也会替换数组/设置。模块应经受控 `getState()` 读取当前状态，不能闭包捕获旧 `state.items`。草稿切换的同步区间、恢复动作与异常处理保持原契约；不让异步任务跨过临时状态切换。提交链、原生同步队列和已提交快照各自只有一个所有者。UI 通过明确命令调用服务；跨层反馈通过少量具名回调连接。

`wrapUserOp` 必须在事件绑定和回调捕获之前完成，且只装饰一次。所有调用者都取得装饰后的命令；不能留下拆分前的裸函数引用。测试 hook 与生产 UI 使用同一实例、同一命令。

### P1：规则收敛与装配失败闭环

- 先为日期差异及当前生产规则补固定时钟的行为用例；以独立期望值为准，避免旧副本互相证明。
- 抽共享日期原语；parse/repeat/reminder 成为唯一来源；更新 Node require 与浏览器依赖。
- 清除 core/native 的算法副本、运行时函数覆盖和必需规则缺失时的静默替代。转发适配只准转换参数或读取设置。
- 依赖验证放在业务启动之前；缺必要模块/导出、错误顺序、损坏脚本时显示可理解的启动失败与重试/刷新入口，ready 明确失败，不进行保存、迁移、排钟或启动业务定时器。不能只 console.error 后留下可编辑但不落库的界面。
- 完整脚本的纯 Web 环境必须正常启动；原生桥延迟/失败保留既有隔离和重试。不要把“无 Capacitor”误判为缺 JS 模块。
- `parse-parity.js` 等依赖 core 源码切片的脚本改为“生产入口确实调用唯一规则 + 结果语义”验证。保留有价值的旧用例，退出码和报告名称如实说明；不保留第二份算法专门供测试。

出口：唯一来源矩阵闭合，缺依赖反例可见失败，Web/Node/原生模拟组合正常，五套测试通过。

### P2：先搬移独立 UI 与平台功能

- 搬移 UI 工具、AI、备份、诊断、引导、内容/视图和表单；每次搬移同步调用点、相关事件绑定和加载链。
- 逐功能拆 `bind()`，初始化按原顺序显式调用。模块求值不启动轮询、不注册全局监听、不自动操作数据；实例启动只执行一次。
- 保持选择器、用户入口、文本意义、焦点、弹层关闭、异步 token、按钮 busy 与错误恢复。
- 表单保存仍通过同一命令与持久化边界；不得为解除循环依赖另起保存路径。

出口：实际 UI 路径可用，无重复监听/定时器、孤立按钮或旧函数引用；受影响测试通过。

### P3：搬移持久化、事务、事项及原生协调

- 先建立模型和状态访问口，再整组迁出提交/重放，随后迁出事项命令与原生协调。不要在单个事务一半仍留旧闭包时改变语义。
- 保持 FIFO 轮到时取快照、提交内不再调用排队 saveAsync、独立快照发布时点、pending-replay 恢复顺序。
- 同事项/周期冲突拒绝，不相关命令按序重放；原生 ACK/snooze/done 的确认必须等权威成功。同事件并发复用 Promise、失败可重试。
- 保持 native 同步的 in-flight/pending/version、deferNativeSync 传递、旧轮结果拒绝与补偿；无变化对账不能重新制造反馈循环。
- 清理入口剩余职责并迁出测试 hook 装配，核对所有模块状态/依赖表。

出口：事务反例在内存、落库和重启后三层都成立；app-core 只负责装配，未形成新的巨型共享上下文。

### P4：生产组合、离线升级与打包收口

- 每次新增运行模块均更新 `index.html` 顺序、SW ASSETS/缓存版本、harness 和打包链；`production-scripts.js` 补完整加载期依赖约束。实际覆盖从生产清单推导，有意替身必须声明且生效，不能重复加载 native 实例。
- 不仅比较脚本数量，还核对集合、顺序、导出及真实调用。检查重名全局导出和错误 root（宿主 global 与 VM/WebView 混用）。
- 实测旧版本已缓存 → 新版升级 → 离线重开，以及新模块下载失败/部分更新。当前 SW install 吞掉 addAll 失败后仍 skipWaiting，需要针对拆分后的资源完整性验证；若可激活残缺资源，做必要的最小修正，保证旧完整版本可继续使用或明确阻止不完整启动，不静默以半套规则运行。不顺带全面重写 SW。
- 在独立输出生成本轮验证包，逐文件比对源码 → www → Android assets → APK `assets/public` 的所有运行 JS 与 index/SW。记录缺失、多余的过时运行脚本及哈希，不只比 app-core。
- `scripts/sync-www.js` 存在 prune；`scripts/android-build.sh` 会覆盖 releases 下固定文件。先核对副作用，优先在专用隔离构建目录运行同步及直接 Gradle 任务并复制到新候选路径，避免覆盖或批量清理现有产物。生产候选/旧证据不作为同步目录。

出口：可检查的源码与资源清单、离线升级证据、测试/构建结果和完整交接。设备条件不足时保留明确缺口，不把构建成功写成实机 PASS。

| A09 | 重放反例 | 缺目标、命令 false/异常、未消费派生 ID 均失败；失败不误确认原生事件，重试可成功；测试能检测绕过命令装饰的入口 |
| A10 | 原生同步与证据 | save/deferNativeSync、前台恢复、桥迟到、旧轮回执、同步中再次保存；排程/取消次数不退化；台账 roundBase、suppressed/cancelled/delivered 与证据未知状态保持 |
| A11 | 真实浏览器 UI | 新建/编辑/低置信度/迟到 AI、ACK/稍后/完成/撤销、整理、未来/归档、笔记/项目/搜索、引导和诊断；焦点/关闭/滚动/按钮恢复正常，无控制台新错误 |
| A12 | 导入导出 | 现有备份格式及密钥排除不变；取消、写失败、连点、后台返回和迟到回执；独立测试数据导出→恢复→重启一致；Android 不回退到虚假下载 |
| A13 | 整页与局部渲染 | 转义/危险协议、含引号 ID、首页折叠大列表和签名碰撞；复用已有有效反例，迁移后真实 DOM 验证 |
| A14 | 离线与升级 | 首次在线缓存后离线打开；旧缓存升级；新脚本失败和部分资源更新；无空白可编辑界面、数据损坏或另一套简化业务规则 |
| A15 | 打包与目标设备 | APK 所有运行资源对应本轮源码；候选真实启动/恢复、通知动作、回前台对账、SAF 和隔离事项提醒；设备和候选身份明确 |
| A16 | 已有优化不退化 | 相同数据和环境比较序列化、renderHome 构建、同步/reconcile 与 schedule/cancel 次数；100/500/2000 事项。报告结构变化与计数，不凭文件变小宣称内存或耗时收益 |

对 A15：普通构建/资源验证纳入实施自测；实机安装和数据操作按用户届时授权执行。需要当前候选的可见送达证据时，必须匹配 trace token、实际可见字段/时间和屏幕，排程成功不算送达。既有 OEM 缺陷作为基线单列；若本次引入回归必须修复，不能借既有缺陷掩盖。没有设备证据时源码验收和目标平台验收分别出结论。

## 7. 交接包与最终判定

实施者交付一个新的 `docs/reviews/verification-runs/<run-id>-app-core-modularization/`，至少包含：

- `module-map.md`：最终模块职责、依赖方向、函数/状态搬移表、公开接口与保留降级清单。

- `source-manifest.json`、本轮 diff/必要源码快照：覆盖全部改动及新文件，使未提交成果也可在隔离环境复现；禁止只给 HEAD 或单一 app-core 哈希。

实施者最终回复必须给出可直接打开的交接文档和源码位置，不仅给测试数量。未经用户授权不提交、不推送，不自动覆盖生产安装。

本任务独立验收顺序：核对交付源码身份 → 审阅模块与唯一来源 → 重跑五套测试及关键故障/重启反例 → 真实 UI/离线/资源闭环 → 按授权核查当前候选实机。报告逐项 PASS / FAIL / NOT_PERFORMED，并区分源码重构、打包和目标设备证据等级。
