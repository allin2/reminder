## 发现的问题（按严重度排序）

### P2-① 浏览器已拒绝通知权限后，开关不引导用户去站点设置重新授权
- **违反条款**：INV-06（丧失提醒能力须明确告知）之**体验面**；§305「关键能力不得偷偷降级而不告知」的同向要求
- **复现步骤**：Chrome → 打开 Web 版 → 点「我的 → 本地通知」开关 → 在系统弹窗里点「阻止」；随后**再次**点该开关
- **期望**：应提示「浏览器已阻止通知，请到站点设置（地址栏左侧锁图标 → 通知）里允许」
- **实际**：`Notification.requestPermission()` 在已拒绝态会立即返回 `"denied"`（不再弹窗），代码把 `settings.notify` 置 false 并 toast `通知权限未授予，将使用应用内提醒`（`lib/app-events.js:616-619`），没有任何指向浏览器设置的引导；用户会以为自己「点过了」而实际永远收不到系统通知
- **证据**：`lib/app-events.js:616-621`
- **影响面**：先点过「阻止」的 Web 用户；需浏览器实测确认三态分支表现
- **建议修复**：在 `Notification.permission === "denied"` 分支改为「去浏览器设置允许通知」文案
- **验证方式**：浏览器里先拒绝、再点开关，观察 toast

### P2-② Web 首页没有任何「网页版无法保证提醒」的告知（§473 / G09 未覆盖 Web）
- **违反条款**：§473「通知权限关闭 → 首页明确告知『无法保证提醒』」；INV-06
- **复现步骤**：Chrome 打开 Web 版首页（不要点保存、不要进「我的」）
- **期望**：首页顶部出现「网页版关掉页面不会有提醒」的常驻告知（对齐原生 `#homeNotice`）
- **实际**：`lib/app-notices.js:70-71` 的 `homeNoticeVerdict` 在 `!native`（非原生 Android）时**直接 `return null`**，首页不渲染任何告知条；Web 用户只有「保存时的 toast」（`lib/feedback.js:129`）和「我的」状态行（`lib/app-views.js:657-659`）两处能知道该限制
- **证据**：`lib/app-notices.js:71`（`if (!native) return null;`）、`:122-133`（`renderHomeNotice` 据此清空 `#homeNotice`）
- **影响面**：Web 新用户第一屏不知道「关掉页面就彻底没有提醒」，容易误以为网页版也能后台提醒
- **建议修复**：让 `homeNoticeVerdict` 对 Web 也返回一条常驻文案（kind 可复用 `switch`/新 kind）
- **验证方式**：纯 Web 首页（未操作）观察 `#homeNotice` 是否为空
