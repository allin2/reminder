# 裁决 · Android 最低版本兼容清理（D75）

D74 已由另一分支使用，本次按任务指定使用 D75。

| # | 问题 | 裁决 | 依据 |
|---|---|---|---|
| **D75** | minSdk 升至 23 后的旧 API 分支 | 删除仅为 API <23 存在的条件与回退，直接保留原 API >=23 路径；不改变 API 23–36 的权限、调度模式、异常回退和投递行为 | `android/variables.gradle` 的 minSdkVersion=23，app 构建引用该值；targetSdk=36，Capacitor 7 |

## 清理范围

- `AlarmScheduler`：两处 PendingIntent 不可变标志、API 21 时钟能力判断、API 23 以下的 setExact 分支。
- `NotificationScheduler`：不可变标志的旧版零值、setExact / set 的旧版回退。
- `SystemBridgePlugin`：两处不可变标志、API 21 时钟判断、API 23 以下的调度分支，以及悬浮窗和电池优化检查的旧版直接放行。
- `AlarmTestReceiver`：不可变标志与悬浮窗检查的旧版直接放行。
- 移除字符串 service lookup 的过时 minSdk 22 说明，保留调用方式；更新仍有效的 API 24/31/34 兼容注释与测试文案。
- D64 权限变异测试以恒 true 模拟绕过权限检查，不再引入恒真的 API 21 条件；其判据不变。

## 保留与验证边界

API 24 Direct Boot、API 24 通知状态兼容、API 26 渠道、API 31 精确权限/振动器、API 33 通知权限及 API 34/35 行为判断仍有实际作用，全部保留。异常或权限失败后的调度回退也全部保留。

已搜索 Java 主代码、Java/JS 测试、lib、app-core.js 和 Gradle：JS 无仅针对 API <23 的分支，未发现相关冗余 @TargetApi / @RequiresApi；无仅测试 API <23 路径的测试需要删除。既有 API 23 的 Direct Boot 回退测试仍有效，保持不变。Gradle 无需修改，www 为生成产物未修改。历史评审与决策中的旧版本描述保留为当时的事实，本记录说明当前支持边界。

风险集中于闹钟路径展开时误删权限或异常回退；本次仅展开恒真版本条件，保留其余判断、catch、调用参数和模式字符串。自动测试不等价于 API 23–36 逐版本真机送达验证。

## 本次验证

- `git diff --check` 通过；再次搜索主代码未留下 API 21/23 的旧版闸门及相关注解。
- 使用本地 Android 36 SDK、缓存依赖和既有项目类，对本次涉及的六个 Java 文件执行 `javac -proc:none -source 21 -target 21`，编译通过；这不代替 Gradle 构建或 JVM 测试。
- `npm test`：15/16 套件通过；native-reminders 在跨时区子进程探针处遇到沙箱 `spawnSync EPERM`，空输出导致 JSON 解析失败。使用 HEAD 原测试文件复跑同位置失败；未修改测试逻辑以绕过限制。
- `:app:testDebugUnitTest :app:assembleDebug` 未能运行：默认 Gradle 缓存只读；复制缓存至 `/tmp` 后 daemon 创建本地 socket 被沙箱以 `Operation not permitted` 拒绝。JVM 测试、APK 构建和逐版本真机验证均不记为通过。
