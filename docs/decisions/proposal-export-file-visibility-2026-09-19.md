# 提案 · 导出后文件不知道去了哪

> **一句话**：用户点「导出数据」，App 弹「已导出备份文件」，但**文件根本没有生成**——
> 手机存储、应用私有目录、缓存里全都没有。提示在撒谎。

**本文只做诊断与方案，代码一行未改**（遵循「未获明确裁决前不实现」）。

## 现象（用户原话）

> 「我知道导出这个行为，但是我并不知道导出在哪。」

## 根因

导出走的是 `app-core.js` 的 `exportData()`，两条分支：

```js
if (navigator.canShare && navigator.canShare({files:[file]})) {
  navigator.share({files:[file]}).then(() => toast("已分享备份"))
                                .catch(() => downloadFile(name, text));   // 分支 A
  return;
}
downloadFile(name, text);
toast("已导出备份文件");                                                    // 分支 B
```

`downloadFile()`（`app-core.js:211`）用的是**网页那套**：造 `Blob` → `URL.createObjectURL` →
造一个隐藏的 `<a download>` → `a.click()`。

**这套做法在安卓内嵌浏览器里没有接应。** 网页里点下载链接，浏览器负责弹"保存到哪"；
但在 App 的内嵌 WebView 里，必须**由 App 自己写代码接住**（安卓的 `DownloadListener` 或
`DownloadManager`）——而本项目的 Android 源码里**一行都没有**（全仓搜索 `DownloadListener` /
`DownloadManager`：零命中，只有无关的 `FileProvider`）。

更糟的是：这套做法**既不报成功也不报失败**，`downloadFile()` 没有任何返回值。
调用方于是无条件弹了 `toast("已导出备份文件")` —— **提示与事实相反**。

## 真机实测（可复算）

| 检查 | 方法 | 结果 |
|---|---|---|
| 分享分支是否可用 | CDP 求值 `typeof navigator.canShare` / `share` | **均为 `undefined`** |
| 因此实际走哪条分支 | 同上 | **分支 B**（`downloadFile` + 无条件成功提示） |
| 点击后界面说了什么 | 读 `#toastText` | **「已导出备份文件」** |
| 手机存储有文件吗 | `ls /sdcard/Download`、`/sdcard/Documents`、`find /sdcard -iname '*安心*'` | **全空** |
| 应用私有目录有文件吗 | `run-as <pkg> find /data/data/<pkg> -newermt ...` | **无任何 `.json`**（只有 IndexedDB / shared_prefs 等常规写入） |
| 系统日志有线索吗 | `logcat -d` 过滤 download/chromium | **零命中**——静默吞掉，连错误都没有 |

**结论：点击导出后，全机范围内没有任何备份文件被创建。**

## 一个必须说清的区分

本次用户按的「导出数据」按钮走的是**旧的备份导出**（`exportData()`），
与本轮新写的 `lib/export-format.js`（对外契约 `attention-inbox.export/v1`）**是两回事**——
新模块**尚未接线**（`index.html` / `www/` / Android assets 均未引用）。
**两条路都有同一个"文件没有出口"的问题**：新模块产出的是字符串，
最终仍要落到"怎么存成文件"这一步。所以本提案的结论对两者都适用。

## 可选方案

| 方案 | 做法 | 好处 | 代价 |
|---|---|---|---|
| **A 存到手机里** | 写安卓侧下载处理，点导出后弹**系统「保存到…」对话框**，用户自己选位置；存完显示**完整路径** | 文件真的存在、位置用户自己定也知道；与导入（系统文件选择器）**对称** | 要写安卓侧 Java 代码，需重新打包 APK |
| **B 只用网页层改成「分享」** | 不做保存，弹系统分享面板发给别的 App | 不用写安卓代码 | **实测不可行**：本机 WebView 里 `navigator.share` 是 `undefined`，代码里那条分享分支**永远不会执行** |
| **C 先诚实化** | 暂不做保存，只把提示改成真实的（明说当前版本导出不可用 + 给出替代做法） | 改动最小、可立即上；**停止欺骗用户** | 导出功能实际仍不可用，只是不再误导 |

### 推荐

**A + C 组合。**

1. **立刻做 C**：把 `toast("已导出备份文件")` 改成如实反馈——检测不到落地就**不许说成功**。
   这是纯粹的"说实话"修复，不依赖安卓侧改动，也不依赖打包。
2. **随后做 A**：安卓侧接住下载，弹系统「保存到…」，并在保存后把路径显示给用户。
   这样"导出到哪"由用户自己决定，"文件在哪"也就有了答案。

**不推荐 B**：它在当前运行环境已被实测证伪，写了也是死代码
（代码里现有的分享分支就属于这种"看起来支持、实际永远走不到"的形态）。
