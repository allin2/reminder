# D76：待整理支持直接完成

日期：2026-10-29

## 问题与决定

待整理中的记录可能已经做完，原有整理、补时间、留待下次、删除都不能表达完成。共用列表卡片增加「已完成」按钮，待处理、未设时间、留待下次三个筛选均提供同一入口，并提供包含记录标题的 aria-label。

直接调用既有 `completeItem(id)`，复用归档、完成时间、周期派生、L04 终态保护和原有 toast 的「前往归档 / 撤销」。不写第二套事项状态变更，不先确认整理，不补时间，也不主动发整理通知或追加保存、重排；提醒取消与重排沿用完成命令及既有渲染链。

## 会话与撤销

会话继续以 ID 为身份，已归档记录退出待整理过滤，清除当前选择后后续操作指向下一条。剩余条数和各筛选计数都按现存待整理记录计算；独立展示本次已完成条数，不混入「已确认」。最后一条移出后复用整理完成页及返回首页按钮。

保留记录的 `NEEDS_REVIEW`，由既有完成撤销恢复原状态后自然回到待整理。会话只跟踪本次完成的 ID 和是否计入进度，在渲染时校准；撤销持久化失败回滚时也能恢复完成计数。已完成动作清除「留待下次」的本次视图标记，撤销后回到待处理。新开会话重置这些临时计数。
