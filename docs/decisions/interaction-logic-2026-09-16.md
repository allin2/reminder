## 〇、这一轮在解决什么

代码与产品文档长期不一致，但一直没定「不一致时谁让步」。上一轮"以远程仓库为准"只解决了**哪条代码线**，
没有解决**代码与 PRD 冲突时谁让步**。结果是：首页挂着「即将到来」、代码用着全屏通知、
低置信度不再即时确认——三处都违反 PRD 的明文，却没人裁决过。

这轮把根问题拆成设计树，逐层问到底。前沿空了，清单如下。

## 一、根决策：原则分级

| # | 决议 |
|---|---|
| **D1** | 五条原则**分两级**。**红线（不可让渡）＝ P1 Attention ≠ Task、P2 Acknowledged ≠ Completed、P4 通知送达 ≠ 用户看到**。**默认值（允许有意识的例外）＝ P3 Future 默认不可见、P5 低交互优先**。 |
| **D2** | 例外的**唯一论证标准**：这个例外会让 §31.4 的「用户主动查看 Future 的频率」**上升还是下降**。PRD 自己把这个指标定义为**不信任信号**，理想方向是下降。 |
| **D3** | 全屏闹钟定性为**产品能力，且仅限「关键」档**；不再作为通用能力，也不再由「待整理」使用。 |
| **D4** | 本轮产出边界＝**决策清单 + 修订产品文档**；**不动代码**。代码改动单独一轮并带测试。 |

### D1 的依据

P1/P2/P4 是这个产品存在的理由——破坏它们，它就退化成一个普通 Reminder。而 P3 与 P5 在实操中会互相打架：
把未来拉上首页服务的是「让托管可信、让用户不必去查」，P3 要的是「不因为存在就提前消耗注意力」——
这是两条不同的轴。把 P3/P5 钉成红线，只会让每一轮都掉进"违规 vs 破例"的循环；降为默认值后，
判断标准变成一条可执行的问句（D2）。

## 二、首页信息架构

| # | 决议 | 依据 |
|---|---|---|
| **D5** | **去掉首页「即将到来」区块**。首页回到「需要注意 / 已看到未完成」两视觉，未来只在「未来」页查看。 | §31.4 把"主动查看 Future"定义为不信任信号、理想方向是下降；「即将到来」等于把这个不信任指标写成首页默认内容。它也是首页从 3 块膨胀到 5 块的主要推手。 |
| **D6** | **「待整理」入口常驻，但降级为弱入口**：一行低对比度文字（**无数字、无强调色**），位置在「现在需要注意」**之后**；进入窗口 ∪ 宽限期时恢复显著性（带数字、提到最前）。 | *2026-09-16 按 V0.2 §12 修订*（原为「只在窗口内出现」）。V0.2 写「弱入口…**仅在 Review Window 或用户主动进入时提高存在感**」——入口不存在，"主动进入"就没有落点，只剩搜索，反而增加操作成本（V0.2 §21 第 2 问）。我当初反对常驻的理由是"白天被一笔账压着"，但那可以用**降低显著性**解决，不必用**隐藏**。 |
| **D7** | **「已看到未完成」永远折叠成一行**（带数量，点击展开），取消现有「≤3 条直接列出」的阈值。 | §17 原文即「默认只展示数量，用户主动点击后查看详细列表」。一行带数字是它能有的最弱存在形式。代价是只有 1 条时也要点一下。V0.2 §12「弱化展示，主动点开才看明细」一致。 |
| **D8** | **「今天已完成」改为空态里的一句**「今天已完成 N 件」——**纯文字，不可点击、无徽标、无强调色**，不新增区块。 | *2026-09-16 按 V0.2 §13 复核后保留*。§13 反对的是把**历史**做成年度总结式数字面板；空态里一句**当天**完成数不属于历史统计，且只在本就不占任何区块时出现，零额外注意力成本。做成可点击入口才会真的变成噪声。 |

## 三、注意力层级与动作集

| # | 决议 | 依据 |
|---|---|---|
| **D9** | **「关键」档的首次提醒使用全屏闹钟**（替代现在的 importance 5 通知）；后续 7 次补充提醒仍走通知。 | 现状完全倒挂：`critical` 没接全屏闹钟，而「待整理」接了。§13.3 已明确闹钟级提醒属关键档；不接会让「关键」这一档名不副实。 |
| **D10** | 关键档**不再增加一层总开关**——录入时默认「普通」，标「关键」本身就是主动选择，已满足 §13.3「该模式必须显式开启，不作为默认录入字段」。 | 再加一层开关只是仪式感。 |
| **D11** | 动作集按**动作深度分两档**：<br>**快捷**（通知栏、全屏闹钟）＝ 我知道了 / 稍后 2 小时 / 完成；<br>**主动**（应用内弹条、表单）＝ 30 分钟 / 2 小时 / 今晚 20:00 / 明天 09:00 / 本周末 / 自定义。 | 从通知栏点「稍后」若要先拉起应用再选时间，用户为了推迟一件事反而要做更多操作——违背 P5。现状的「全屏稍后＝写死 10 分钟」是纯遗留，且出现在最重要的关键档界面上。 |
| **D12** | 全屏闹钟**保留「关闭」按钮**，语义＝止响但**不表态**（不写 ACK、不记账、不消耗提醒预算）。 | 一个人被闹钟吵醒、只想让它停下时，若唯一出路是「我知道了」，系统就是在**逼他谎报"我看到了"**，而 ACK 会停掉后续全部补充提醒——这直接绕过 D1 定为红线的 P4。 |

## 四、弹条（应用内提醒横幅）

| # | 决议 | 依据 |
|---|---|---|
| **D13** | 弹条**只能通过点 × 关闭**；点击页面其他区域不再关闭它。 | P4 说「送达 ≠ 看到」，同理「关掉 ≠ 看到」。既然关闭会消耗提醒预算，它就必须是一个明确动作，不能被环境误触触发。受现状伤害最大的是 critical——恰恰是唯一"绝不漏"的那一档。 |
| **D14** | 弹条**挂 10 分钟后自动收起**；收起是**纯展示行为**，不做任何记账，下个 tick 仍可再弹。 与 D13 的"关闭"严格区分：关闭＝用户主动，消耗 30 分钟抑制；收起＝系统行为，零记账。 | 弹条不是模态框，它占的是首页顶部——而首页正是用户来处置其他事情的地方，一直挂着会让首页无法使用。 |
