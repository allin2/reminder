# D41 · 统一事务模型（2026-09-17）

## 决议

原生 ACK / snooze / done 不再先修改共享 `state` 再尝试回滚，而是采用：

1. 从轮到该动作时的最后确认状态复制不可见草稿；
2. 在草稿内完成版本校验后的状态变更、周期派生和事件台账；
3. 仅以 IndexedDB（无 IDB 时为 localStorage fallback）的提交结果判定成功；
4. 提交未决期间，同一事项或同一 `seriesId` 的用户命令明确返回 `false`，提示“这条事项正在保存 · 请稍后重试”，不关闭表单/稍后面板，不显示成功；
5. 不相关事项的已接受状态命令按原顺序记录；原生提交成功后重放到草稿，再发布到 UI；
6. 提交失败时不发布草稿，原生事件不确认，UI 保留最后确认状态与不相关事项的用户命令。

因此，原生动作派生的下一期在创建提交确认前不可见；用户不能对一个尚未成立的对象收到虚假成功反馈。提交确认后，该实例使用稳定 `id`，并通过 `repeatParentId` 明确绑定父实例。重放直接注入原创建 id；同一父实例最多一个下一期，不再按数组顺序事后改 id。

通知栏和全屏闹钟共用 `handleAlarmAction` 的 Promise 边界。通知栏的已送达通知只在业务 Promise 成功后移除；失败时保留供重试。重放缺少目标、执行异常、业务 reducer 返回 `false` 或创建 id 未消费均为事务错误，不能静默跳过。

## 状态与入口关系

| 入口 | 事务关系 |
|---|---|
| 同事项/同周期的编辑、ACK、完成、稍后、删除、恢复、停止周期、整理确认 | 原生草稿提交未决期间明确拒绝；落定后可重试 |
| 不相关事项的新建/编辑/状态操作 | 状态命令；原生草稿提交期间记录并按序重放 |
| 项目删除对事项的 `projectId` 清理、提醒弹条关闭 | 若影响事务域则拒绝，否则纳入命令记录 |
| 截止排程对账、真实送达回调、原生时间迁移 | 同上，已纳入命令记录 |
| `promoteDue` 自动推进 | 草稿提交期间延后，下一拍重算 |
| 导入、载入示例、清空全部 | 草稿提交期间拒绝执行并给出“正在保存”反馈，避免覆盖事务域 |
| 通知栏 ACK/snooze/done、全屏闹钟动作 | 同一隔离草稿与权威提交边界 |
| 笔记、项目、设置 | 不由动作草稿发布覆盖；各自保存仍经过 FIFO 提交链 |

## 不变量

- 未提交原生动作不进入可见状态、原生事件台账或原生排程投影。
- 同事项/同周期冲突命令不会先报成功再静默丢失；拒绝时内存、权威存储和表单输入保持一致。
- 失败事件不假记已处理；同事件并发复用同一提交 Promise。
- 同一父实例最多一个周期下一期，派生身份跨重放与重启稳定。
- 提交成功前不移除通知栏动作对应的已送达通知，不确认全屏闹钟队列事件。
- IndexedDB 为权威，localStorage 只是提交成功后的尽力镜像；无 IDB 时 fallback 单独生效。
- 保存失败保留内存修改并明确提示，后续保存会再次携带当前状态。

旧 D36–D40 记录的是逐步暴露问题的历史方案；D41 替代其“先乐观写共享 state、失败后猜测回滚范围”的核心机制，不删改旧报告。
